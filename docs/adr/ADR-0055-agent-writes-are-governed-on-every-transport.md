# ADR-0055 — An agent's writes are governed the same way whichever transport they arrive on

**Status:** Active
**Decided:** 2026-07-04

## The decision

A mutating call made by an agent is resolved to its tier and, when
confirm-first,
staged for a human — whether it arrives as an MCP tool call at `/mcp` or as a
REST
request carrying a passport as its bearer credential. Agents keep full REST
write
access; those writes are simply governed identically to tool calls. One tier
table
serves both doors, keyed from the operation annotations in the contract, so a
tier
is declared once. A mutating operation an agent reaches that maps to no tier is
refused rather than admitted, so a forgotten annotation fails closed. Operations
an
agent must never perform for itself — approving or rejecting an approval,
consent
and data-subject writes, pipeline configuration — reject an agent caller
outright.

## Why

The tier model was originally wired only into the MCP tool path, where the tier
is a
property of the tool. The REST layer carried no tier model at all, so a
write-scoped passport calling a mutating REST endpoint bypassed the single most
important rule of the agent surface. The system claimed one admission point
while
one of its two transports had none. Making admission a property of the action
rather
than the transport is what makes that claim literally true.

## What it binds in this repository

- `backend/internal/compose/agentgate.go` is the REST-side admission middleware.
  `agentGate` wraps the handler chain, `prepareAgentGate` resolves the tool spec
and
  the tier for the routed operation, and an unknown, human-only or unresolvable
  operation is refused.
- `backend/internal/platform/auth/admit.go` (`Gate.Admit`) is the shared admission
  point both doors call. It lives in `platform/auth`, so a module or extension
  cannot own or bypass it.
- `backend/internal/compose/agentpolicy_gen.go` is the one tier table, generated by
  `backend/tools/gen-agentpolicy` from the `x-mcp-tool` and `x-agent-access`
  annotations in `backend/api/crm.yaml`. Its `accessHumanOnly` entries are the
  operations that reject an agent caller.
- `backend/api/crm.yaml` states the contract invariant near the top of the file:
  every mutating operation must carry either `x-mcp-tool` (a tier) or
  `x-agent-access`.
- `backend/internal/compose/agentcommandbothdoors_test.go`
  (`TestBothDoorsResolveOneOperationToOneCommand`) proves the two doors agree.
- `backend/internal/compose/agentegress_test.go` (`TestAnUnregisteredVerbIsRefused`)
  proves the fail-closed default.
- `backend/internal/compose/agenttierfloor.go` re-keys the same table by verb and
  record type, because a tool call names a verb where a REST call names an
operation.

## History

Adopted from the retired specification, decided 2026-07-04. Rewritten in plain
language 2026-08-19. It replaced an earlier stopgap that refused agent writes on
REST entirely; that refusal is withdrawn, and agent REST writes are admitted and
gated instead. ADR-0026 still owns which actions are auto-execute and which are
confirm-first, and ADR-0036 owns the approval token mechanics.
