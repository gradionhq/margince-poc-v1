# ADR-0120 — An extension is its own Go module, and being present is what enables it

**Status:** Active
**Decided:** 2026-08-19 (the tier shipped earlier; this is the first ratified record of it)

## The decision

An extension is a directory under `extensions/<name>/` holding its own Go
module. It imports only the published surface under `backend/pkg/`, never the
product's internal packages. There is no enablement switch and no registry to
edit: a unit present in the tree is a unit that ships, and deleting the
directory removes it.

The wiring is generated rather than written. `make composition` reads the units
present and produces `build/composition/`, which is ignored by git. The
`composition/` directory at the repository root is a committed empty stub so
that a bare `go build` resolves without running the generator first.

Each unit carries a `manifest.generated.json`, derived from the contract rather
than hand-written, so a unit cannot claim a capability the contract does not
grant it.

## Why

Two problems needed one answer. Customer-specific work had to be possible
without forking the product, and the product had to stay upgradable while that
work existed. A plugin system with a registry solves neither well: the registry
becomes a second place to forget, and a plugin that reaches into internals turns
every upstream refactor into somebody's broken deployment.

A separate Go module makes the boundary real rather than conventional. An
extension that reaches past `backend/pkg/` does not compile. That is a better
guarantee than a rule in a document, because it holds on the day nobody is
reading the document.

Presence-as-enablement removes the class of bug where a unit exists, looks
installed, and silently does nothing because a list somewhere was not updated.

## What it binds in this repository

- `extensions/` holds five first-party units, each with its own `go.mod`: `de`
  (German jurisdiction rules), `dispact-connector`, `notes`, `yogi`, `zalo-oa`.
- `backend/pkg/extension/` is the entire surface an extension may import.
  Anything outside it is internal and unreachable from a unit.
- `make composition` runs `backend/tools/gen-composition`, writing the ignored
  `build/composition/`. Every build lane runs it.
- `composition/extensions_gen.go` at the root is the committed vanilla stub —
  generated, and not to be edited by hand.
- Each unit's `manifest.generated.json` is regenerated by `make gen`; a
  hand-edited or stale manifest fails the drift gate rather than being silently
  healed.
- `extensions/` is covered by the same license-header, craftsmanship and
  public-reference gates as `backend/` — a first-party unit ships the same
  product and meets the same bar.

## History

The decision was made and built during 2026-07 and 2026-08 but never got a
ratified record: the draft sat on an unmerged branch numbered ADR-0069, which
already belonged to a different decision about embedding width, so it could not
land. `CLAUDE.md` and `AGENTS.md` cited ADR-0069 for the extension tier
throughout that period, pointing at the wrong record.

Written as ADR-0120 on 2026-08-19 to end the collision. The embedding-width
decision keeps ADR-0069.
