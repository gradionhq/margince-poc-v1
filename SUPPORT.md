# Getting help

Margince is a pre-release proof of concept. There is **no support
commitment**: issues are answered best-effort by a small team that is
busy building the thing. Setting that expectation is fairer than implying
a queue exists.

Where to go, in the order worth trying:

1. **[docs/README.md](docs/README.md)** — the documentation index.
   [docs/reference/make-targets.md](docs/reference/make-targets.md) covers
   the build and dev commands, and
   [docs/reference/configuration.md](docs/reference/configuration.md) the
   config file, flags, and operational endpoints. Most "how do I" answers
   are already written down.
2. **[docs/explanation/backend-onboarding.md](docs/explanation/backend-onboarding.md)**
   — the codebase map and reading order, if the question is "where does
   this live".
3. **[CONTRIBUTING.md](CONTRIBUTING.md)** — how a change gets from your
   machine to `main`, and what the gates check.
4. **A GitHub issue**, using one of the templates. A reproducible bug
   report gets attention faster than a question, because it can be acted
   on directly.

Two things that do **not** belong in a public issue:

- **A security vulnerability.** Report it privately — see
  [SECURITY.md](SECURITY.md).
- **A conduct concern.** Mail conduct@gradion.com — see the
  [Code of Conduct](CODE_OF_CONDUCT.md).
